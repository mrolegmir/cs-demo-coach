# v1.1.1 — reliability fixes from the architecture review

This patch addresses the five reproduced review findings. It adds no new game
diagnosis or scoring thresholds. See [ADR 30](decisions/0030-atomic-worker-completion-and-identity.md).

## Observable behaviour

- An interrupted worker cannot turn a committed analysis into a failed match
  because its source demo was already removed. Completion is atomic; cleanup is
  retried by the API after commit.
- A late result or failure from an earlier attempt cannot overwrite a newer
  attempt. Repeating a successful completion is harmless.
- Players with identical nicknames remain separate participants. Their evidence
  is checked by ID, and personal priorities are attributed by ID. A generated
  suffix distinguishes colliding display references. Old report prose stays as
  saved; ambiguous old names do not acquire another player's personal priorities.
- Concurrent requests share one weekly budget. The final check occurs when the
  request is admitted; a previously displayed available slot is not a reservation.
- Direct and HTTP workers both trigger the same opted-in automatic coaching.

## Validation/demo

The regression tests use synthetic player names and isolated PostgreSQL databases:

```sh
go test ./internal/coach -run 'TestDuplicateNames|TestLegacy'
go test ./internal/brief -run TestInputDuplicateNamesPreservesIdentity
go test ./internal/store -run 'TestCompletion|TestLateAdvice|TestManualBriefAnd|TestAutomaticAndManual|TestConcurrentUploads'
go test ./internal/worker -run TestLostCompletionReplyKeepsSavedResult
go test ./internal/web -run 'TestCompletionAdaptersAndDurableCleanup|TestCleanupContinuesAfterRemovalError'
```

DB tests need `CSDC_TEST_DATABASE_URL`. Full checks are `go test -race ./...`,
`go build ./...`, `go vet ./...`, `golangci-lint run`, and `npm test` in `bot/`.
Real parser tests additionally need the local demo fixtures.

Local validation on 2026-11-02 passed: the full race suite with isolated
PostgreSQL 18 and real demo fixtures, follow-up race tests for the final changed
packages, build, vet, lint (zero issues), and all 12 bot tests.

## Rollout requirements

This document describes the change; it does not record a deployment.

1. Back up the database and keep the previous API image and worker executable.
2. Stop/drain the old worker before the API update. Migration 13 is additive.
3. Update the API and worker together. Old worker write endpoints return 409;
   no fallback to the old non-atomic protocol is permitted.
4. Verify a new detect job, automatic coaching, quota rejection and eventual
   demo cleanup. Existing matches, reports, friends and practice are preserved.
5. For direct database workers, set the same `CSDC_QUOTA_UPLOADS` and
   `CSDC_QUOTA_COACHING` as the API (defaults 15; zero means unlimited).

Rollback must stop v2 workers and switch API/worker together. The additive cleanup
column can remain for a code rollback; avoid dropping it or overwriting saved
reports merely to roll back code. Rollback returns the older reliability limits.
